# Deploy

Status: done
Source: [results-site decisions](../../open-questions.md#pipeline) (“Separate `build` and `deploy`”, “Hosting”); mapped with the user on 2026-10-15.

## Story

As the maintainer, I want to publish the current state to GitHub Pages with one command, so that the link in the README and in talks shows a site that matches exactly one commit.

`pnpm deploy:site`, run from `site/`, calls `experiments/deploy-site.py`. It stops before building off `main`, with uncommitted changes under `research/` or `site/`, or while HEAD is not yet on `origin/main`. It then runs the complete build and publishes nothing if that build leaves a diff under `research/`. Otherwise it appends one commit, `Deploy <short sha>: <subject of the main commit>`, to `gh-pages` — an orphan branch on the first deploy — holding `site/dist/` plus `.nojekyll`, and pushes it. Every build, local ones included, serves the site beneath `/agentic_coding_lab/`, and every page's stamp names the HEAD commit, short and linked to GitHub. Turning GitHub Pages on is done once by hand, after the first deploy, on the user's go.

## Built

Implemented with the `exact-coding` skill. 10 pytest tests in `experiments/tests/test_deploy_site.py` run against a real repository with a bare one as origin, the build replaced by a shell one-liner (123 Python tests in all). 5 Vitest tests — 3 in `src/site-links.spec.ts`, 2 in `src/TopBar.spec.tsx` — plus the existing link and stamp expectations moved to the base path (153 Vitest tests in all). Readings adopted: “on `origin/main`” means HEAD is `origin/main` or one of its ancestors, as the last fetch knows it; a failing build publishes nothing and passes its exit code on; a build that only adds files under `research/` counts as a change; `gh-pages` mirrors `dist/`, so a page gone from `dist/` is gone from the branch; a deploy commits even when `dist/` is unchanged (`--allow-empty`), so each deploy is one commit. Deviations: Vitest's project plugins pin Vite's `base` to `/`, so the links do not read `import.meta.env.BASE_URL`; the base path lives in `src/site-base.ts`, read by `astro.config.mjs` and by `site-links.ts`, which now holds every page link (`rq-link.ts` and `workflow-link.ts` are gone). The host's git is 2.34, without `worktree add --orphan`, so the first deploy checks out the orphan branch inside a detached worktree.
