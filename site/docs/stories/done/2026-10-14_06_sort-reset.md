# Sort reset

Status: done
Source: the user on 2026-10-14: once a column was sorted, the RQ's own row order, which may carry meaning, could not be restored.

## Story

Clicking the label header (`workflow`, `model`, …) restores the RQ's own row order. The column a table is sorted by is marked, so a reader sees that the order is not the RQ's. Both choices were the user's: the label header rather than a third click on the column, and a visible mark.

## Built

Implemented with the `exact-coding` skill; four tests in `src/ResultTable.spec.tsx` ("Sort reset and marking"), 128 Vitest tests in all. The label header is a button titled "Back to the RQ's order"; it is left out when no factor varies, because an empty button would have no accessible name and such a table has nothing to reorder. The sorted header carries `aria-sort` with the numeric order the column shows: best first is `ascending` for a lower-is-better metric and `descending` otherwise, and the second click flips it (`sortedOrder`). It is shown bold on a tinted background. The rule "the first click sorts best first, the next reverses" now lives once, as `sortsBestFirst()` in `result-table.ts`, used by the sorting and by the mark.
