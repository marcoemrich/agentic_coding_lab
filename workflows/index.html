Baselines

baseline-oneshot-v1-cconeshotClaude Codead hocbranch

A one-shot baseline for Claude Code (arm: oneshot). The agent reads the exercise, implements the solution in a single autonomous pass and runs whatever verification it finds appropriate. Tests are not required. There is no test list, no phase structure, no refactoring rules and no subagents.

baseline-end-refactor-only-v1-agent-ccend-refactor-onlyClaude Codead hocbranchparent: baseline-oneshot-v1-cc

A test-after baseline for Claude Code (arm: end-refactor-only). It has three sequential phases and no cycle. First the agent implements the solution without tests. Then it writes a test suite from the specification, with a test for every spec example and every clarifying question, and gets it green. Last comes a single refactoring pass. That pass runs in an isolated refactoring subagent with a fresh context and applies the Four Rules of Simple Design, the Absolute Priority Premise, a naming evaluation and a mandatory refactoring attempt.

baseline-iterative-v1-cciterativeClaude Codead hocbranch

External skills

external-kesseler-2026-09-30-cckesselerClaude Codead hocvendored

An external workflow for Claude Code (arm: kesseler): Lada Kesseler's TDD skill from lexler/skill-factory, commit 474433af2e (Apache-2.0), vendored unchanged together with its ZOMBIES reference; the upstream eval files are not included. Tests are planned up front as one-line test comments and checked for completeness against ZOMBIES. They are then worked through one at a time, with predicted failures, a two-step Red (first a compile failure, then an assertion failure), a simplify step and a refactor at every green. A final evaluation looks for missed tests and hardcoded values. Everything runs inline in one context. The lab runs the skill in its auto mode, treats the prompt as the approved plan and supplies the test command.

external-pocock-2026-09-04-ccpocockClaude Codead hocvendored

An external workflow for Claude Code (arm: pocock): the tdd, code-review and codebase-design skills from Matt Pocock's mattpocock/skills, commit 6654f6b6 (MIT), vendored unchanged. Red–Green works in vertical slices, one test at a time, at seams agreed in advance. There is no up-front test list, and refactoring is explicitly not part of the loop. Once the suite is green, a code review runs in two parallel subagents, one for coding standards and one for the spec, and reports its findings without acting on them. The lab adds autonomous execution, takes the seams from the prompt, points the review at the written files and the prompt instead of a Git diff and an issue tracker, and supplies the test command.

external-superpowers-2026-09-04-ccsuperpowersClaude Codead hocvendored

An external workflow for Claude Code (arm: superpowers): the test-driven-development skill from Jesse Vincent's Superpowers collection, release v6.3.0 (MIT), vendored unchanged. Red–Green–Refactor under a strict test-first rule — code written before its test is deleted. No up-front test list; the next test is chosen as work proceeds, all inline in one context. The lab only replaces the human-in-the-loop checkpoints with autonomous execution.

external-tcr-kentbeck-2026-09-14-cctcr-kentbeckClaude Codead hocvendored

An external workflow for Claude Code (arm: tcr-kentbeck): the tcr-kentbeck skill from Pietro Di Bello's xpepper/tcr-skill, commit 48c16c0 (MIT), vendored unchanged. It is classic TCR: tiny steps, each run against the full suite, and every reverted step is appended to a failure log. Test-first is not required. There is no test list, no phase structure and no refactoring rules, and everything runs in one context. The lab adds only autonomous execution, the test command and an isolated local Git repository to commit into.

external-tcrdd-bsene-2026-09-14-cctcrdd-bseneClaude Codead hocvendored

external-tcrdd-git-gamble-2026-09-14-cctcrdd-gambleClaude Codead hocvendored

An external workflow for Claude Code (arm: tcrdd-gamble): the tcr skill from Pietro Di Bello's xpepper/tcr-skill, commit 48c16c0 (MIT), vendored unchanged. It is TCRDD driven by the git-gamble tool. Every Red, Green and Refactor step bets on its expected test outcome, then commits if the bet holds and reverts if it does not; a new test that passes straight away is reverted too. There is no up-front test list and no refactoring rules beyond keeping behaviour unchanged, and everything runs in one context. The lab adds autonomous execution, the test command, an installed git-gamble and an isolated local Git repository.
