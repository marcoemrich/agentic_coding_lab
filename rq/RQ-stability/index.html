F-stability.2 — Workflow Stability Is Not Uniform; subagents-v1 Has a 10 % Outlier Rate Despite a Low Typical Value; single-context-v1 Is the Broadest Workflow

Statement: Stability indicators per cell (cognitive_max as the main example):

Workflow μ σ CV (σ/μ) IQR Outlier rate (>2σ)
baseline-inline-tdd-v1-cc 21.80 3.43 0.157 5.50 0 %
baseline-oneshot-v1-cc 18.80 3.40 0.181 3.25 10 %
baseline-iterative-v1-cc 16.20 3.40 0.210 5.00 0 %
exact-single-context-v1-cc 14.50 4.59 0.316 7.75 10 %
exact-hybrid-v1-cc 5.20 2.30 0.442 ~3 0 %
exact-subagents-v1-cc 4.40 4.25 0.965 1.25 10 %

Three stability profiles:

  • oneshot-v1/iterative-v1/inline-tdd-v1 are "band-shaped": σ ~3.4 with a moderate IQR (3–6), values concentrated around the mean. These workflows consistently produce similar code quality — both the mean values and the individual runs are comparable.
  • **subagents-v1 is "concentrated with a tail": IQR only 1.25 (8/10 runs in [2, 4]), but one outlier at 17 pulls σ and the mean up. Median = 3, compared to a mean of 4.4. The typical subagents-v1 performance is considerably better than the mean suggests — but 1 in 10 runs derails.
  • **single-context-v1 is "broad": σ 4.59, IQR 7.75. single-context-v1 runs are generally unpredictable in complexity — the shared context lets very different implementations arise path-dependently.
  • **hybrid-v1 is "compact without a tail": σ 2.30, all 10 runs in [1, 7], 0 % outlier rate. hybrid-v1 reaches near-v4 median performance (5.2 vs 4.4) without subagents-v1's 1-in-10 refactor dropout. Plausible mechanic: the isolated refactor subagent is formally invoked in every TDD cycle (see F-stability.6, cycle σ=0.82) — the "refactor phase skipped" failure mode from subagents-v1 is structurally excluded by the hybrid construction.

The CV is misleading as a stand-alone stability measure: subagents-v1 has CV 0.965 (the highest relative spread) although 9/10 runs lie in an extremely narrow range [2, 4] — this only arises because μ is small and one outlier dominates the σ estimate. IQR and outlier rate tell the correct story: subagents-v1 is in the typical case the most stable workflow, with occasional refactor dropouts.

Data basis: 50 runs. The outlier rate column is very coarse at n=10 (a single outlier = 10 %).

Mechanic of the subagents-v1 outlier (inspected manually): The one subagents-v1 run with cognitive_max=17 contains the entire logic in a single 28-line arrow function — the refactor phase did not split the code into smaller functions. Correctness is nevertheless 100 %. This suggests a rare failure mode in which subagents-v1 performs no structural improvement in the refactor subagent phase.

Statement: From 1000 random trials in which a three-element subsample is drawn from each cell and the workflow ranking is computed from it, the following hit rate against the n=10 ground-truth ranking results:

For calibration: with 5! = 120 possible rankings, chance would be 0.83 %. All values are therefore far above chance.

Nevertheless: the full 5-workflow ordering cannot be reliably reconstructed with n=3, particularly in the middle of the field (oneshot-v1, iterative-v1, single-context-v1 on cognitive_max). For longest_function and smell_total, n=3 suffices in only ~25 % of cases.

That does not mean, however, that all statements from n=3 are worthless:

  • Reproducibility score (the share of three-element subsamples with a mean within ±20 % of the n=10 mean): ≥ 0.92 on all outcomes for oneshot-v1, iterative-v1, inline-tdd-v1. n=3 delivers robust estimates of the mean here.
  • subagents-v1 as the winner on cognitive_max is reliably identifiable even with n=3 subsamples — subagents-v1 has a ~3× smaller typical value than every other workflow.
  • inline-tdd-v1 as last on cognitive_max is equally robust (inline-tdd-v1 mean 21.8, σ 3.43; no other workflow reaches these values).

The weakness of n=3 lies in the middle of the field — oneshot-v1 vs iterative-v1 vs single-context-v1 differ by ~2–5 points on cognitive_max at σ ~3.4, which is not discriminable with n=3.

Consequence for the lab methodology:

  • Statements such as "subagents-v1 is clearly better than everything else" or "inline-tdd-v1 is worse than non-TDD": n=3 suffices (large effect size + low IQRs of the non-v4 workflows).
  • Statements such as "workflow A is marginally better than workflow B" (e.g. iterative-v1 vs single-context-v1): n=10+ required, otherwise the ranking is unstable.

F-stability.6 — TDD Discipline Forms Workflow-Characteristic Bands

Statement: The four TDD discipline indicators (cycle_count, refactorings_applied, predictions_correct_rate, tests_passed_immediately) separate the six workflows into four discipline classes:

Workflow cycle_count μ±σ refactorings_applied μ±σ predictions_correct_rate tests_passed_immediately μ±σ Discipline class
baseline-oneshot-v1-cc 1.0 ± 0 0.0 ± 0 — 1.0 ± 0 structurally empty
baseline-iterative-v1-cc 1.0 ± 0 0.0 ± 0 — 1.0 ± 0 structurally empty
baseline-inline-tdd-v1-cc 1.5 ± 0.97 0.1 ± 0.32 — 0.5 ± 0.97 phantom TDD
exact-single-context-v1-cc 6.7 ± 2.67 6.0 ± 3.09 100.0 % 0.9 ± 1.66 broadband discipline
exact-subagents-v1-cc 7.8 ± 0.92 5.9 ± 2.02 98.1 % 3.3 ± 2.87 narrow bands, strict discipline
exact-hybrid-v1-cc 8.3 ± 0.82 4.0 ± 1.63 99.4 % 3.3 ± 3.02 narrowest bands, strictest discipline

Rationale: The four classes are consistently defined across three indicators:

  • oneshot-v1/iterative-v1 (structurally empty): no cycles, no refactorings, no predictions — structurally without TDD discipline (by workflow definition). tests_passed_immediately = 1 is an artifact of the metrics code: the tests written after the implementation all run green at once.

  • inline-tdd-v1 (phantom TDD): despite the formal TDD instruction in the workflow, no real cycles (μ=1.5 — typically a single mega cycle), practically no refactorings (μ=0.1), no consistent prediction format (predictions_total = 0 across all 10 runs, hence excluded from the rate column). Replicates the F-prompt-correctness.10 pattern from the archive (rqs-v1): inline-tdd-v1 fulfills TDD only nominally.

  • subagents-v1 / hybrid-v1 (narrow bands, strict discipline): cycle σ < 1.0, refactorings σ ≈ 1.6–2.0, predictions ≥ 98 %. hybrid-v1 even has the narrowest cycle band of all (σ=0.82), enforced by the hybrid construction: each cycle must be formally concluded by the refactor subagent before the next red phase starts in the main context.

  • single-context-v1 (broadband discipline): means as high as subagents-v1 for cycles and refactorings, but a 3–4× broader spread (refactorings σ=3.09 vs subagents-v1 σ=2.02). The shared single context allows different path realizations — one run can have 0 refactorings, another 8. On the long CLI kata claim-office, this spread collapses into a clear loss of discipline (RQ-workflow-tradeoff F-workflow-tradeoff.4): single-context-v1 falls to 3.4 cycles there, while subagents-v1 and hybrid-v1 stay at 25–37.

tests_passed_immediately (an indicator of over-implementation): subagents-v1 and hybrid-v1 have the highest mean (3.3). Plausibly: in both workflows the test list is laid out completely in advance, after which the first real test is made green — in the process several it.todo tests are also satisfied by the minimal green implementation. This is not a discipline breach in the narrower sense but a structural consequence of the test-first phase.

Data basis: 60 runs (6 workflows × n=10), opus-4-7-no-thinking, game-of-life-example-mapping and game-of-life-prose (for oneshot-v1/iterative-v1). For inline-tdd-v1, predictions_correct_rate drops out because inline-tdd-v1 does not emit the prediction format consistently.

Consequence for workflow selection: The discipline bands are orthogonal to code quality — single-context-v1 reaches high discipline means with a broad spread, hybrid-v1 reaches similar means with the narrowest spread. If reproducibility of the discipline indicators is itself a workflow goal (e.g. for auditable development logs), hybrid-v1 is the most robust choice.

  • exact-hybrid-v1-cc delivers the lowest spread (σ=0.005) AND at the same time the highest mean (level with oneshot-v1/iterative-v1). On the complexity metrics subagents-v1 was dominant; on test strength hybrid-v1 is dominant. The hybrid architecture (skill-based red/green + isolated refactor) appears to eliminate subagents-v1's test-strength spread without losing test strength itself.
  • subagents-v1 again shows the tail risk documented in F-stability.2: σ=0.080, min 0.735 — several subagents-v1 runs lie clearly below the typical subagents-v1 value. The isolated green phase appears to occasionally produce weak test generalization.
  • single-context-v1 likewise has an elevated spread (σ=0.036, min 0.843) — the single context is more robust than subagents-v1 on test strength, but not as smooth as oneshot-v1/iterative-v1/inline-tdd-v1/hybrid-v1.
  • oneshot-v1/iterative-v1/inline-tdd-v1 (non-TDD or minimal TDD) cluster at mean ≈0.95, σ≈0.008 — despite differing workflow philosophies they are indistinguishable in test strength on game-of-life.

Consequence for H1 (the n=3 question): For mutation_score, n=3 would be particularly unreliable for subagents-v1 — three draws from a distribution with σ=0.080 and min 0.735 can, depending on luck, deliver a completely different picture of subagents-v1. For hybrid-v1 and oneshot-v1/iterative-v1/inline-tdd-v1, n=3 would by contrast be sufficient (σ < 0.01). The outlier asymmetry from F-stability.2 repeats itself for test strength: subagents-v1 has a broad tail distribution, other workflows do not.

Data basis: 60 game-of-life runs, opus-4-7-no-thinking, EM for inline-tdd-v1/subagents-v1/single-context-v1/hybrid-v1 and prose for oneshot-v1/iterative-v1. Stryker 8.6.0.

Caveats

  • Single model: Only opus-4-7-no-thinking. A model change could shift the stability picture — RQ-model-quality suggests a higher Sonnet spread, but only at n=3.
  • Single kata: Only Game of Life (library form). Other katas (claim-office, mars-rover) could show different stability profiles, particularly if the problem has a more variable solution space.
  • Tail estimation: n=10 gives rough σ estimates with wide confidence intervals. Outlier rates of 10 % each correspond to a single run — the true rate can lie between 0 and 30 %.
  • Subsampling as a validity measure: The P(n=3 ranking = n=10 ranking) numbers are themselves derived from 50 runs — a hypothetical n=20 could show finer conditions for n=3 reliability.
  • subagents-v1 refactor dropout: The 1-in-10 run with cognitive=17 is a concrete occasion for improving the subagents-v1 workflow (the refactor phase must be triggered more reliably). This is not part of this RQ, but is documented for future workflow iterations.
